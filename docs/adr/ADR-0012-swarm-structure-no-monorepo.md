# ADR-0012: структура роя — клетки, не монорепо

Статус: принято (вопрос PID 1, 2026-11-05: «есть ли там в репо проекты,
которые проще объединить? или этого лучше не делать? как вариант
предпочтительный? много мелких или один крупный проект?»; решение поручено
рою — «без вариантов») · Дата: 2026-11-05

## Контекст

9 репо: 8 клеток генома + дом commons (external-house). После передачи рою
решения по каталогу (ADR-0011) владелец поднял вопрос структуры: много
мелких репо или один крупный проект; есть ли кандидаты, «которые проще
объединить».

Факты осмотра (живые клоны, 2026-11-05): singulyar — 1,2 ГиБ, 2012 файлов;
voice-atlas-llm — 176 МиБ (модели); singulyar-llm — 7 файлов в git
(веса 468 МБ — в Release-ассетах по манифесту); rumu — 5 файлов (мембрана
клетки-указателя); global-video-platforms-registry — 38 файлов; дом
commons — своя жизнь с другими агентами (ритуал волн).

## Рассмотрение по законам

Один крупный проект (монорепо) отвергнут:

- мембрана клетки (Закон 1) определяет запреты и лицензию на клетку; в
  рое три лицензии (MIT×5, Apache-2.0×2, CC-BY-4.0×1) — смешение в одном
  репо размывает мембраны и усложняет согласие;
- ядро должно оставаться лёгким семенем (Закон 5): влитый singulyar тянул
  бы 1,2 ГиБ в каждый клон ядра;
- дом commons вливать запрещено самой природой дома: там другие агенты,
  своя жизнь и ритуал волн — слияние = трение с чужой работой;
- CI-метаболизм клеток независим; в монорепо он дробится paths-фильтрами
  и болеет целиком при чужих правках.

Слияние ради слияния тоже отвергнуто: Закон 2 (окно) делит клетку по боли
контекста; обратная операция оправдана только обратной болью.

## Решение

1. **Много мелких клеток — правильная структура роя.** Монорепо не заводить.
2. **Критерий слияния клеток** (на будущее): сливать только когда клетка
   спит (нет метаболизма) И её роль не покрыта другой клеткой И содержимое
   дублируется. Ныне таких нет: singulyar-llm спит по CI, но его веса живут
   Release-схемой (боль лимита git решена) и роль (метаболизм) уникальна —
   не сливаем ни одну клетку в этом такте.
3. **Объединение, которое напрашивалось, уже сделано**: тело РУМУ живёт
   веткой singulyar@rumu, репо rumu — клетка-указатель (Закон 3: хаб хранит
   пины, не контент). Открытый пункт «перенос тела в самостоятельный репо»
   ЗАКРЫТ решением: не переносить — перенос создаёт новое репо, новый CI и
   новые Pages без пользы.
4. **Внутриклеточные дубли — сливать да**: в ветке rumu жили два каталога
   (свой JSON плеера и зеркальный catalog.js со сломанной связкой id);
   ADR-0011 сводит данные к своим и снимает внешнюю зависимость.

## Следствия

- Геном остаётся 8 клеток; дом — external-house.
- Будущие предложения о слиянии клеток проверяются критерием п. 2 —
  по факту спячки, уникальности роли и дублирования содержимого.
- Дубликаты данных внутри клетки сводятся на общий источник (как каталог
  РУМУ по ADR-0011).
