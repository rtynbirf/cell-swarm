# ADR-0008: лицензия источника данных bldub — проверка выполнена, открытой лицензии нет

Статус: принято (остаток снят агентом роя, решение за Человеком) · Дата: 2026-11-05

## Контекст

Тело РУМУ (ветка `rumu` репо singulyar, пин 30bcf37b) питается каталогом bldub:
`catalog.js` — зеркало 249 тайтлов, снятое с `new.bldub.live/api/v3/index.php?a=GetTitles`
(названия, описания, рейтинги, хотлинк постеров на `bldub.com`). В геноме (swarm.json,
клетка `rumu`) стояла честная пометка «лицензия источника данных bldub требует
проверки». Проверка поручена агенту роя — у него есть веб; ЮРИСДИКЦИЯ НЕ ПРЕДПОЛАГАЕТСЯ
(правило автора): ниже — только формулировки источника и их прямые следствия.

## Факты (проверено живым вебом 2026-11-05)

1. `bldub.com` жив; это стриминг BL/GL-сериалов с русской озвучкой.
2. Футер сайта, дословно: **«Весь материал на сайте представлен исключительно
   для домашнего ознакомительного просмотра»** — то есть источник сам рамирует
   свой материал рамкой «домашний просмотр», не «повторное использование».
3. В футере есть страницы **«Пользовательское соглашение»** и **«Правообладателям»**
   (внутренние ссылки id=65, id=66). Их точный текст из песочницы получить не
   удалось: обе отдают 408 (таймаут), web.archive.org — denial. Это ограничение
   зафиксировано честно: текст соглашения НЕ ПРОЧИТАН, а не «прочитан и ничего нет».
4. Публичной лицензии на API и данные каталога нет нигде: ни open-data, ни CC,
   ни условий переписывания рядом с `api/v3`.
5. Произведения в каталоге (сериалы) — вещи третьих лиц; сам сайт держит страницу
   «Правообладателям» (takedown-процедура), т.е. прав на произведения не декларирует.

## Вывод (fail-closed)

Отсутствие найденного разрешения — это «нет права», а не «разрешено». Данные
каталога bldub — нелицензированный материал третьего лица; их зеркало (описания,
хотлинк картинок) нельзя вливать в публичное ядро роя. Тело РУМУ уже несёт
`catalog.js` в публичном singulyar@rumu — этот риск лежит на владельце репо
(rtynbirf) и может быть снят только его решением (PID 1); рой факт фиксирует,
за него не решает.

## Варианты для Человека (не решение роя)

- **(а) Спросить источник**: письменное разрешение bldub на использование
  каталога — самое чистое; заодно можно попросить прислать текст их соглашения.
- **(б) Облегчить зеркало**: оставить в `catalog.js` только id/названия/ссылки,
  описания и картинки не копировать и не хотлинкать — вес риска падает на порядок.
- **(в) Свой каталог**: составить каталог самостоятельно из открытых описаний
  с указанием источников — дольше, но полностью своё.

## Последствия

**Положительные:** юридический остаток снят по существу — вместо «требует
проверки» в геноме стоит проверенный факт с датой и методом; из `next` ушёл
последний пункт, исполнимый без человека.

**Отрицательные / цена:** страницы соглашения не прочитаны (таймаут) — если
Человек откроет их в браузере и передаст главное, ADR пополняется (храповик:
только добавляется). До решения Человека `catalog.js` в ядро роя не входит.

**Обратный мерж:** не требуется — новое ядро роя и геном на дом не влияют.
