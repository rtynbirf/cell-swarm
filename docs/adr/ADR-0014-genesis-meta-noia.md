# ADR-0014: GENESIS_EXEC в рое — протокол мета-нойи клетки, dry-run по умолчанию

Статус: принято (мандат Хозяина, волна TH-RHO-1/TH-SWM-1, чат 2026-11-10:
«дерезай твори мути… прежде чем мутить — поищи лучшие мировые тренды практик;
сделай и настрой так, как ни у кого нет»; решение поручено агенту роя) · Дата: 2026-11-10

## Контекст

В НОУСе (дом документов) живёт генезис-контур: `docs/genesis/runtime-protocol.md`
(GENESIS_EXEC: фазы 1–5 + Ω LIMIT), `docs/genesis/invariant-minimal.md`
(инвариант Δ≠Σ, 7 операторов), `docs/genesis/session-decomposition.md`
(12-тактный стек обработки обструкции). Все три — на main nous пином
`ac3f0ff8ed7ce27ad00ec91ff3953db893e91eeb` (проверено живым GitHub API 2026-11-10).
К ним добавляется операционализация метрик ρ̇ (`docs/genesis/metrics-operationalization.md`
в nous) и мостовой документ (`docs/genesis/cell-swarm-binding.md` в nous).

Вопрос: как рой относится к GENESIS_EXEC — исполнять, отвергнуть, или связать указателями?

## Рассмотрение по законам

- **Закон 3 (указатели, не импорты):** генезис-спеки не копируются в рой — пинуются
  (SHA + путь + дата + метод). Рой хранит точку входа и пины, НОУС — истину спеки.
- **Закон 4 (храповик):** живое исполнение фаз = изменение поведения; ему нужны
  тесты вперёд. Сегодня рой принимает только декларацию: dry-run, события в
  worklog/SEALS (append-only хэш-цепь — уже существующее стигмергическое поле роя).
  Новых типов крови не вводится: словарь типов — грамматика дома и не расширяется молча.
- **Закон 1 (клетка автономна) + согласия:** фазы, меняющие состояние клетки,
  исполняются только с до-фактовым согласием PID 1 (грамматика ADR-0017 дома).
  `consent/grants.json` этой волной не расширяется: «согласие на всё подряд — не согласие».
- **Закон 2 (окно):** грамматика событий моста помещает метрики в атрибуты события;
  окно клетки не должно впитывать чужой контекст — события стерильны (без контента,
  только метки и числа).

## Решение

1. GENESIS_EXEC принимается роем как **гипотетический протокол мета-нойи клетки**;
   режим исполнения каждого контура моста — **DRY_RUN** (события логируются,
   действий нет) до появления тестов, приёмки и отдельного решения.
2. Мост фиксируется с обеих сторон: точка входа роя — настоящий ADR; точка входа
   НОУСа — `docs/genesis/cell-swarm-binding.md`. Пины НОУСа:
   `runtime-protocol.md`, `invariant-minimal.md`, `session-decomposition.md`
   на `ac3f0ff8…` (живая проверка 2026-11-10); пин на метрики обновляется при
   слиянии PR nous (канон `make pins` — живой вызов с датой).
3. Триггеры фаз — только по измеримым условиям (RHI-полосы метрического файла);
   MAST-коды (3 категории / 14 режимов отказа, arXiv:2503.13657) — предохранители:
   неверно специфицированная фаза не получает право даже на dry-run; три события
   одной клетке за окно = клетка в dry-run до разбора Хозяином.
4. **HITL:** OVERCLOCK_INPUT, TRIGGER_META_NOIA, FORK_BOMB, Ω LIMIT — никогда
   не исполняются автоматом; вердикт PID 1 до факта. Eved-функция (honeypot) —
   dry-run навсегда и без доступа к крови.
5. Настоящий ADR не меняет геном, bootstrap, workflows и CI роя. Следующий шаг —
   тикет роя с тестами событийной грамматики (храповик: сначала тесты, потом код).
