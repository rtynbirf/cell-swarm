# ADR-0004: геном вместо тулчейна

Статус: принято · Дата: 2026-11-05

## Контекст

Мировая практика монорепо (Nx, Turborepo, Bazel) решает цену сборки кэшированием —
и приносит тулчейн, который сам требует обслуживания. Рою из одного человека это не
по силам: бюджет внимания — четвёртый ресурс (родство с домом: W-0025).

## Решение

Сложность живёт в данных, не в инструментах: геном `swarm.json` + горстка скриптов
на stdlib. Инструмент можно добавить, когда боль названа замером, — не раньше.

## Альтернативы

- Bazel/Nx сразу — сила на масштабе, которого нет; цена обучения сейчас.
- Никаких скриптов, всё руками — храповик не заводится: люди повторяют, скрипты нет.

## Последствия

**Положительные:** порог входа в рой = читать один JSON; мутации генома — диффы.
**Отрицательные / цена:** при росте числа клеток придётся звать кэширующий билд —
сигнал тот же, что и у митоза.

## Проверяемость

Если `make verify` дольше пяти секунд или геном перестал влезать в один экран —
пересмотреть (метрика названа).
